Maintenance

EasyWAF generates a self-signed certificate named easywaf on first run so the GUI is never served over plain HTTP. To replace it, upload your own under Certificates and select it here — browsers stop warning once you use a certificate they trust for the name you reach this interface by.
Whichever is selected cannot be deleted while it is in use. If it later becomes unusable or is removed outside the GUI, EasyWAF falls back to easywaf and logs why, rather than failing to start — this page is the only place the setting can be corrected, so the interface has to come up.
Takes effect after a restart.

This is one setting for the whole appliance rather than per site: the TLS version and cipher suites are fixed when a listener binds its port, before the client has said which site it wants, so sites sharing a port necessarily share them. Certificates are per site — those are chosen by SNI during the handshake.
There is no weak-cipher option to pick: nothing below TLS 1.2, and no RC4, 3DES or CBC-SHA1, is implemented at all. Modern refuses clients that only speak TLS 1.2.
A change here takes effect when listeners are next bound, which means after a restart.

Edit the line down to the suites your policy permits. Names are checked on save — an unrecognised one is refused rather than quietly dropped, so a restriction you think is in force always is. Order is not yours to set: the server offers them strongest first.
Every suite here is AEAD. If a standard forbids CBC, or RC4, or 3DES, or static-RSA key exchange, that is already satisfied — none is implemented, so none can be selected. The TLS 1.2 suites are all ECDHE, so all have forward secrecy. TLS13_ suites apply to TLS 1.3 and the rest to TLS 1.2; leaving one family out under Compatible means clients of that version cannot connect.
Supported by this build: {{ tls_ciphers_all }}
This applies to the management interface as well as to proxied sites, and takes effect after a restart.

Let's Encrypt (ACME)

Where the CA sends expiry warnings. Setting it registers an account on first use, which is also how you accept Let's Encrypt's subscriber agreement.

Start with staging. Browsers will still warn, because staging certificates are not trusted — but it proves the whole exchange works without spending production quota. Production allows only five failed validations per hostname per hour, which a first attempt burns through easily. Switch once staging succeeds.
Changing the address or the directory re-registers the account: staging and production are separate registries, so credentials from one mean nothing to the other.
For validation to succeed the site's name must resolve to this host from the public internet, and port 80 must be open to it — HTTP-01 validation always arrives there, and that is a property of the protocol rather than a choice EasyWAF makes. EasyWAF binds port 80 itself, whatever ports your sites use, and answers the challenge in the proxy; there is no directory to configure.

Trusted Proxies

Leave empty unless something else sits in front of EasyWAF. With it empty — the default — the client address is the address that connected, and X-Forwarded-For is ignored entirely.
Only list proxies you control. X-Forwarded-For is a header, so any client can send one; if EasyWAF believed it unconditionally, anyone could claim any address and walk straight past country rules — and past the IP block lists coming in a later release. It is believed only when the connection itself came from an address listed here.
Single addresses and CIDR blocks both work, IPv4 and IPv6. An entry that does not parse is refused rather than skipped, since a silently ignored range is one you would believe was covered.
This affects who the Traffic Monitor, the country rules and CAPTCHA clearance think the client is. Getting it wrong in the other direction matters too: behind a proxy with nothing listed, every request looks like it came from that proxy, so one visitor solving a CAPTCHA would clear it for everyone.

Flow Logs

One line for every proxied request — the site, the client, the method and path, the verdict, and the rules and score behind it. Off by default: sending traffic off the box is a decision, not an assumption.
Nothing is written locally. Every request is already in Traffic Monitor with the same detail, so a file beside the database would be the same data in a worse format. This exists to get the stream off the box — into a collector that can hold more history than an appliance should, and chart it across several of them.
Lines are sent without waiting: if the collector is slow or gone, lines are dropped and the count is reported, rather than the proxy slowing down behind them.

A hostname or an IP address — not a URL, and without the port. UDP, which is what EasyLog ingests.

514 unless the collector says otherwise.

Audit Log

Every change made through this interface is written to {{ log_dir }}/audit.log with the account that made it. It is always on and stays on this machine: an audit trail sent somewhere by the machine it accuses is worth less than one that survives the network being down, and there is no switch for it — an appliance that cannot say who changed it is not one to run.
A file per day, kept {% if log_keep_days == 0 %}indefinitely{% else %}{{ log_keep_days }} days{% endif %}, then deleted — nothing to set up in logrotate. The directory and that number are the one part of logging still set in config.toml, since the directory has to be known before the database is open and a container needs to point it somewhere that survives the container.

Rule Updates

Looked at on start and every six hours. Nothing is ever applied on its own — the Policy Manager shows which policies are behind, and applying is a button someone presses. An auto-applied bad rule is an outage across every site using that policy.
Turn it off on an installation with no outbound access, or one whose rules are managed by hand.

Where the manifest and the sets are fetched from. Leave it empty for the default, {{ rule_update_default }}.
Pointing this elsewhere does not lower the bar. An update is applied only if the manifest carries a valid signature from the key in rules/key.gpg, which ships with EasyWAF, and only if the set matches the SHA-256 that signed manifest gives for it. A channel serving something else is refused, whoever it belongs to.

The channel is copied to {{ mirror_dir }} on the same schedule as the check above, and installing a set reads from there rather than the network — so a set can be installed or updated with the channel unreachable.
The copy is not trusted for being local. The signature and the per-set hash are checked when a set is installed, exactly as they would be over the network. Editing a file in that directory does not install anything; it makes the install refuse.
A set the mirror does not have — published since the last sync — is fetched over the network as before.
