Upstreams — what this node has seen of each backend

The backends themselves are the Upstream field above: edit the list to add one, weight one, park one with off, or remove one. This is the part the field cannot say.
A backend that stops answering is taken out of the rotation after three failures in a row, and one request is let through thirty seconds later to find out whether it is back. Unreachable counts as a failure and so does a 5xx; a 404 does not, since that is the application answering. A request that can safely be sent again is retried on another backend, so one backend failing costs nothing — a request whose body is still arriving cannot be, and gets a 502.
This is this node's own observation and is not shared with any other: a backend one node cannot reach may be perfectly reachable from another.

HTTPS

Leave the port empty to serve this site over plain HTTP only. Setting it serves HTTPS as well as HTTP — the two are independent, so enabling one never switches the other off. Certificates are chosen per site by SNI, so many sites can share one HTTPS port.

Each presents this site's certificate. A site with an HTTPS port and no certificate cannot complete a handshake, so the port is not bound at all rather than bound and failing every connection.
The first port listed is the one an HTTP-to-HTTPS redirect sends visitors to, since a redirect has to name one.
