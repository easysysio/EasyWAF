Two different files for two different jobs. A snapshot is the whole database, exactly, for when the host is gone. An export is a readable description of the configuration, for cloning an installation, reviewing a change or keeping it in version control. A snapshot is the one to trust for recovery: an export leaves out what it does not describe, and that is gone at restore.
Snapshot the database is {{ db_size }} on disk
A snapshot is a secret. It holds the private key of every certificate this appliance serves, every account's password hash, and the key that signs sessions. Keep it where you would keep those — not in a ticket, not in a shared folder, not in git.

Taken while EasyWAF runs, without stopping it: SQLite copies the database through its own consistent view, including writes not yet folded into the main file. Traffic history is included — it is part of the database — so a snapshot is roughly the size above, or less.

Export the configuration

A readable TOML file: policies with the rule sets they hold and the rules they switched off, rules written here, exclusions, sites and their upstreams, certificates, IP entries, published-list choices, country rules and settings. Objects are named, never numbered, so it can be imported into another installation, compared with an earlier export, or kept in version control. Traffic history, the session key and the ACME account are never in it.

— anybody holding the file can then impersonate every site it names. Without them, a certificate travels as its public half and is re-uploaded or re-issued where the file is imported.
— off by default: cloning an installation should not silently clone who may sign in to it.
Import a configuration

An import makes this installation match the file. What the file has is created or changed; what only this installation has is removed. Two exceptions: accounts are only ever added or updated, never deleted — and never the account running the import — and this appliance's own management certificate stays. Traffic history is untouched.
