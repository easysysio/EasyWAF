Leave this off unless the site answers 502 and the log says the backend's certificate could not be verified. With it on, the connection to the backend is still encrypted but its identity is not checked, so use it only for a backend on a network you trust. It has no effect on an http:// backend, or on the certificate visitors see.

Only matters with more than one backend, and only for a backend that keeps something in memory: a session, an in-process cache. Without it a client's requests are spread across the pool, and the symptom is a user logged out at random rather than anything that looks like a proxy problem. The client is pinned by a signed cookie, not by its address — many clients share one address behind NAT.

Sign-in

{% if realms %}

A realm is where names and passwords come from — see Settings → Sign-in Realms. The application behind needs no change: it is told who the visitor is in a header.

Asking on the whole site breaks anything that is not a person in a browser. A sync client, a mobile app, WebDAV, CalDAV, an API or a webhook does not fill in a form: it gets a sign-in page where it expected an answer, and fails without saying why. In front of Nextcloud or Immich that is every desktop and phone client at once. Name the paths that need a sign-in — /admin, /settings — or leave the ones machines use open below.

A path covers itself and everything below it: /admin covers /admin/users, not /administrator. It is matched on the path as the application reads it, so //admin and /x/../admin are /admin.

Both are removed from every request to this site before they are set, so a visitor cannot send one. A sign-in is asked for over HTTPS only.

Rate limit

How many requests one client may make to this site, counted per address (an IPv6 client by its /64). Addresses on the policy's allow list and trusted proxies are never counted.

DetectionOnly refuses nothing: requests over the limit are served and marked would block in Traffic Monitor, so a limit can be watched before it enforces. Refuse answers 429 Too Many Requests with a Retry-After saying when the client may send again. Show a CAPTCHA lets a person who answers it carry on; only a page load is shown one, and a client past twice the limit is refused instead. Every request counts, refused ones too, so a client that keeps sending stays over.
A browser loading one page can make dozens of requests for its images and scripts, and a sync or mobile client far more — Nextcloud and Immich clients among them.
