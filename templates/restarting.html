{# Shown once, as EasyWAF stops itself to apply a restore. It stands alone rather than extending the layout: the layout draws a menu from the signed-in session, and that session is about to belong to a database that is being replaced — a restored snapshot brings its own session key and accounts. #} EasyWAF — restoring

Restoring the snapshot

EasyWAF is stopping to swap the snapshot in, and starts again by itself. The database it replaces is kept, and if the snapshot does not start, it is put back automatically.

Waiting for EasyWAF to come back…

You will sign in with the accounts in the snapshot — it carries its own, and its own session key, so the session you have now ends. Sites are not served during the restart, which normally takes a few seconds.

If nothing happens for a minute, EasyWAF is not running under a service manager that restarts it. Start it again yourself; the snapshot is applied as it starts.
